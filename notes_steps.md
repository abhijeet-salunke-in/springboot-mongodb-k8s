# Spring Boot + MongoDB + Docker + Kubernetes Project

## Part 1 — Project Setup and Local Testing

This project is a Student Management application built using:

- Java 21
- Spring Boot 3.5.4
- Spring Data MongoDB
- MongoDB 7
- Docker
- Kubernetes
- Kubernetes StatefulSet
- Kubernetes Deployment
- Kubernetes Services
- MongoDB Replica Set
- AWS EBS CSI storage
- AWS LoadBalancer

The final architecture contains:

```text
                    AWS LoadBalancer
                           |
                           | :8080
                           v
                 Spring Boot Service
                           |
                  +--------+--------+
                  |                 |
                  v                 v
             Spring Boot       Spring Boot
                Pod 1             Pod 2
                  |                 |
                  +--------+--------+
                           |
                           v
                  MongoDB Replica Set
                           |
             +-------------+-------------+
             |             |             |
             v             v             v
        mongodb-0      mongodb-1      mongodb-2
```

# 1. Project Objective

The objective of this project is to deploy a Spring Boot Student Management application with MongoDB on Kubernetes.

The project demonstrates the following:

1. Build and test a Spring Boot application.
2. Connect Spring Boot with MongoDB.
3. Containerize the Spring Boot application using Docker.
4. Push the Docker image to Docker Hub.
5. Create a MongoDB StatefulSet in Kubernetes.
6. Create persistent storage for MongoDB.
7. Configure a MongoDB 3-node Replica Set.
8. Insert student data into MongoDB.
9. Verify replication between MongoDB nodes.
10. Deploy Spring Boot using a Kubernetes Deployment.
11. Connect Spring Boot to the MongoDB Replica Set.
12. Expose the Spring Boot application using a Kubernetes LoadBalancer.
13. Access the application from a browser.
14. Verify the `/students` REST API.

## Important directories

### `src/main`

Contains the Spring Boot application source code.

This includes the application classes, controllers, models and MongoDB repository-related code.

### `target`

Contains the build output generated by Maven.

The Spring Boot executable JAR is generated here after running the Maven build.

### `yamls`

Contains the Kubernetes YAML manifests used to deploy the application and MongoDB.

### `Dockerfile`

Contains the instructions used to create the Docker image for the Spring Boot application.

### `pom.xml`

Contains the Maven project configuration and application dependencies.

# 8. MongoDB Connection

The application uses Spring Data MongoDB to communicate with MongoDB.

The important configuration is the MongoDB connection URI.

For the Kubernetes deployment, the URI eventually becomes:

```text
mongodb://admin:password123@mongodb-0.mongodb:27017,mongodb-1.mongodb:27017,mongodb-2.mongodb:27017/school?replicaSet=rs0&authSource=admin
```

This URI contains several important components:

```text
mongodb://
        |
        +--> admin:password123
        |       |
        |       +--> MongoDB username/password
        |
        +--> mongodb-0.mongodb:27017
        +--> mongodb-1.mongodb:27017
        +--> mongodb-2.mongodb:27017
                |
                +--> MongoDB Replica Set members

school
   |
   +--> Database name

replicaSet=rs0
   |
   +--> Replica Set name

authSource=admin
   |
   +--> Authentication database
```

> Note: The credentials shown above were used during this project. In a production environment, credentials should be stored in a Kubernetes Secret rather than directly in a Deployment manifest.

# 9. Student API

The Spring Boot application exposes the student API.

The main endpoint used during testing is:

```text
GET /students
```

When the application is running locally, test it using:

```bash
curl http://localhost:8080/students
```

The endpoint returns student information stored in MongoDB.

Example response:

```json
    "name": "Abhijeet Salunke",
    "email": "abhi@gmail.com",
    "age": 18,
    "course": "DevOps"
  }

```

# 10. Understanding the Application Flow

When a client requests:

```text
GET /students
```

the request flows through the Spring Boot application:

```text
Client
  |
  | GET /students
  v
Spring Boot Controller
  |
  v
Student Repository
  |
  v
MongoDB
  |
  v
Student Documents
  |
  v
JSON Response
```

The controller receives the HTTP request and calls the repository.

The repository communicates with MongoDB through Spring Data MongoDB.

MongoDB returns the student documents.

Spring Boot converts the result into JSON and sends it back to the client.

# 12. Why We Test Locally First

We follow the deployment process in stages:

```text
Stage 1
Local Spring Boot Application
        |
        v
Stage 2
Docker Container
        |
        v
Stage 3
Docker Hub Image
        |
        v
Stage 4
Kubernetes
        |
        v
Stage 5
MongoDB StatefulSet
        |
        v
Stage 6
MongoDB Replica Set
        |
        v
Stage 7
Spring Boot Deployment
        |
        v
Stage 8
AWS LoadBalancer
        |
        v
Browser / External Client
```

Testing locally first helps isolate application problems before introducing Docker and Kubernetes.

If the application does not work locally, there is no reason to troubleshoot Kubernetes yet.
